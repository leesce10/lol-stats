# 인게임 오버레이 앱 (In-Game Overlay) 기획서 — 초기 컨셉

> ⚠️ **초기 컨셉 문서.** 현행 관리 문서는 [overlay.md](overlay.md). 플랫폼은
> **Overwolf → Electron으로 피벗**됨(영어강제·승인게이트 회피). 아래 Overwolf 서술은
> 역사적 기록이며 현행 아키텍처는 overlay.md를 따른다.

> 게임 중 알면 좋은 정보를 화면 위 오버레이 + TTS로 알려주는 데스크톱 앱.
> 이 사이트에서 다운로드·설치. 웹과 별도 repo, 백엔드는 공유.

---

## 1. 한 줄 정의

> **"게임 화면을 떠나지 않고, 지금 이 순간 필요한 정보를 눈과 귀로 받는다."**

웹사이트(밴픽/맞라인/조합)는 *게임 밖*에서 쓰는 도구. 이 오버레이는 *게임 안*에서 쓰는 도구다.

---

## 2. 왜 별도 프로젝트인가 (아키텍처 결정)

웹앱(Next.js/Vercel 서버리스)과 오버레이(데스크톱 네이티브)는 런타임이 근본적으로 다르다. 한 repo에 합치지 않는다.

```
[오버레이 앱]  ← 새 repo (Overwolf)
   │  ① 로컬 Riot API → 인게임 상태·아이템·참가자
   │  ② lol-stats 백엔드 호출 ───────────┐
   ▼                                     ▼
 투명 오버레이 + TTS              [lol-stats 백엔드]  ← 이 repo
                                  /api/live/* 새 엔드포인트
                                  + Supabase + 기존 matchup/teamcomp 재사용
                                  + Riot API 키는 서버에만 보관
```

**원칙:**
- Riot API 키는 절대 데스크톱 앱에 넣지 않는다(추출 위험). 남의 전적 조회는 전부 백엔드 경유.
- 라인 평가·티어 계산 로직은 기존 `src/lib`, `src/data` 재사용 → 백엔드 API로 노출.
- 웹사이트가 다운로드 페이지 + 백엔드를 동시 호스팅.

**플랫폼: Overwolf.** Riot 공식 인정 오버레이 플랫폼(Porofessor·Mobalytics가 사용). 풀스크린 게임 위 렌더링, LCU 이벤트, 밴 안전성을 해결해준다. 메모리 읽기/인젝션 방식은 계정 정지 위험이라 배제. 인게임 데이터는 Riot 공식 **Live Client Data API**(로컬, 합법)만 사용.

---

## 3. 데이터 소스 (무엇으로 가능한가)

| 소스 | 위치 | 키 필요? | 제공 |
|------|------|---------|------|
| **Live Client Data API** | 로컬 `https://127.0.0.1:2999/liveclientdata/*` | ❌ 불필요 | 게임 중 전 플레이어 아이템·레벨·스코어·이벤트(킬/드래곤 등). **MVP는 이것만으로 가능.** |
| **LCU API** | 로컬 League Client (Overwolf가 이벤트 노출) | ❌ 불필요 | 챔프 셀렉트·로비·현재 게임 참가자 명단 |
| **Riot Web API** | 너희 백엔드 → Riot 서버 | ✅ **프로덕션 키** | 남의 매치 히스토리(팀 전적 분석용). Development Key(24h)로는 배포 불가 → 별도 승인 필요. |

> ⚠️ 이게 단계를 가르는 핵심: **아이템 오버레이는 로컬 API만으로 즉시 가능**하지만, **팀 전적 분석·TTS 브리핑은 Riot 프로덕션 키 승인이 선행**되어야 한다. ([riot-production-key-application.md](../riot-production-key-application.md) 참고)

## 4. MVP (1차) — 아이템 오버레이

**범위:** 상대 라이너가 라인에 복귀(= 인벤토리에 새 아이템 등장)했을 때, 오버레이에 아이템 아이콘 + 한 줄 텍스트로 알린다.

**동작:**
```
Live Client Data /allplayers 폴링 (1~2초 간격)
↓
각 플레이어 items 배열 diff → 새 완성 아이템 감지
↓
상대 라이너(내 맞라인)에 변화 발생 시
↓
오버레이: [아이템 아이콘] + "상대 미드 존야 완성 — 갱호응 주의" 같은 짧은 텍스트
↓
N초 후 자동 페이드아웃
```

**MVP가 답해야 할 것:**
- 내 맞라인이 누군지 식별 (포지션 매칭)
- "새 아이템"의 의미를 한 줄로 (예: 방관/마관/생존기 → 위협 변화). 챔피언 데이터 기반 멘트는 기존 `src/data` 재사용 가능.

**MVP에서 제외(2차로):** TTS, 팀 전적 분석, 챔프 셀렉트 단계, 백엔드 호출(아이템 의미 멘트를 로컬 정적 데이터로 처리하면 1차는 백엔드 없이도 가능).

**의도적으로 안 하는 것 (no silent scope creep):** 메모리 읽기, 적 시야/쿨다운 추적(Live Client Data 미제공·ToS 위험), 입력 자동화.

---

## 5. 이후 단계

- **2차 — TTS 팀 브리핑.** 게임 시작 시 참가자 명단(LCU) → 백엔드가 각자 전적 조회 → "탑이 이번 시즌 폼 좋음 / 정글 라인 자주 꼬임" 같은 데이터 근거 멘트를 TTS로. **Riot 프로덕션 키 필수.**
- **3차 — 인게임 정보 TTS + 확장 오버레이.** 주요 이벤트(스펠/궁/오브젝트 타이밍) 브리핑.

---

## 6. 현실 점검 (reality-check 통과 항목)

- [ ] **Riot 프로덕션 키** — 2차부터 필수. 신청·승인 리드타임 확인. (MVP는 불필요 → 먼저 출시 가능)
- [ ] **Overwolf** ToS·심사·배포 플로우 검증, 개발자 등록.
- [ ] **차별화** — Porofessor가 이미 하는 것과 무엇이 다른가? → 한국어 + TTS 음성 브리핑 + 초보 친화 멘트가 가설. "팀운" 같은 근거 약한 멘트는 신뢰 훼손이므로 **데이터로 뒷받침되는 것만** 말하게 설계.
- [ ] **"있으면 좋겠다"가 아니라 "이것 때문에 깐다" 수준인가** — MVP(아이템 오버레이)는 op.gg/Porofessor 대비 약함. 진짜 차별점은 2차 TTS 브리핑일 가능성 → MVP는 "기술 검증 + 배포 파이프라인 구축"으로 위치 규정.

---

## 7. 열린 결정

- repo 이름/위치 (예: `lol-overlay` 별도 repo)
- 백엔드 공유 방식: 신규 `/api/live/*` 라우트 vs 공용 패키지 분리 → **API 경유 권장**(키 보안)
- TTS 엔진: OS 내장(무료) vs 클라우드 TTS(자연스러움, 비용)
